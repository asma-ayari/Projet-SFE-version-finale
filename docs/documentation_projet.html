1. Introduction et objectifs du projet

Ce projet de fin d'études (PFE) consiste en la conception et le développement d'un chatbot intelligent bilingue (français/arabe) dédié à la sécurité routière en Tunisie. L'application utilise l'intelligence artificielle pour répondre aux questions des utilisateurs concernant le code de la route tunisien, la signalisation, et les bonnes pratiques de conduite.

Objectifs principaux

  • Accessibilité bilingue — Répondre en français et en arabe avec détection automatique de la langue
  • Réponses précises — Utilisation de la technique RAG (Retrieval-Augmented Generation) basée sur les documents officiels tunisiens
  • Détection des panneaux — Reconnaissance des panneaux routiers par texte et par image (caméra)
  • Authentification sécurisée — Système complet avec JWT, Google OAuth2, et réinitialisation par email
  • Sécurité robuste — 8 techniques de sécurité implémentées (OWASP)
  • Interface moderne — Design inspiré de ChatGPT/Claude avec conversations persistantes

6. Pipeline RAG (Retrieval-Augmented Generation)

6.1 Qu'est-ce que le RAG ?

Le RAG combine la recherche d'information (retrieval) avec la génération de texte (generation) pour produire des réponses précises et sourcées. Contrairement à un LLM classique qui "invente" ses réponses, le RAG les base sur des documents réels.

6.2 Pipeline en 5 étapes

Question utilisateur │ ▼ ┌─────────────────┐ │ 1. Détection │ language_detector.py │ langue │ (FR ou AR par caractères Unicode) └────────┬────────┘ ▼ ┌─────────────────┐ │ 2. Recherche │ vector_store.py + Pinecone Cloud │ vectorielle │ Embedding → cosine similarity → Top K └────────┬────────┘ ▼ ┌─────────────────┐ │ 3. Construction │ Contexte = chunks pertinents │ du prompt │ + instructions système (FR ou AR) └────────┬────────┘ ▼ ┌─────────────────┐ │ 4. Génération │ Groq API → Llama 3.1 8B │ LLM │ Temperature: 0.3 (factuel) └────────┬────────┘ ▼ ┌─────────────────┐ │ 5. Détection │ sign_detector.py │ panneaux │ 41+ panneaux avec images SVG └────────┬────────┘ ▼ Réponse enrichie (texte + panneaux)

7. Authentification et autorisation

7.1 Méthode 1 — Email + Mot de passe (Local)

Inscription: Client → POST /api/auth/register → Validation Pydantic (A2: force MDP) → bcrypt.hash(password) → INSERT INTO users → JWT access + refresh Connexion: Client → POST /api/auth/login → Rate limit check (A3) → SELECT user WHERE email → bcrypt.verify(password) → JWT access (15min) + refresh (7j) → Client

7.2 Méthode 2 — Google OAuth2

Client → Bouton Google → Google Identity Services (One Tap/Popup) → Google ID Token (credential) → POST /api/auth/google → httpx → googleapis.com/tokeninfo (vérification) → get_or_create_user(google_id, email, name, avatar) → JWT access + refresh → Client

7.3 Méthode 3 — Mot de passe oublié

Étape 1: POST /api/auth/forgot-password { email } → Génère code 6 chiffres → Stockage mémoire (10min) → Email SMTP Étape 2: Utilisateur entre le code dans l'interface Étape 3: POST /api/auth/reset-password { email, code, new_password } → Vérifie code → Valide force MDP (A2) → bcrypt.hash → UPDATE user

7.4 Système JWT dual (Access + Refresh)

Token Durée Secret Usage
Access Token 15 minutes JWT_SECRET_KEY Authentifier chaque requête API (header Authorization)
Refresh Token 7 jours JWT_REFRESH_SECRET_KEY Renouveler l'access token sans re-login

Le frontend renouvelle automatiquement l'access token 1 minute avant son expiration via scheduleTokenRefresh().

8. Sécurité — 8 techniques implémentées

Les techniques suivent les recommandations OWASP Top 10 pour la sécurité des applications web.
Code Technique Fichier Description
A2 Validation mot de passe fort schemas/auth.py Min 8 chars, 1 majuscule, 1 minuscule, 1 chiffre, 1 spécial. Validateur Pydantic field_validator.
A3 Rate limiting login (anti brute-force) core/security.py + api/auth.py Max 5 tentatives par IP en 5 minutes. Retourne 429 si dépassé. Classe RateLimitStore.
A5 Token refresh + expiration courte services/auth_service.py Access token 15min + refresh token 7j. Deux secrets JWT distincts. Auto-refresh frontend.
A6 Changement de mot de passe api/auth.py PUT /api/auth/change-password. Vérifie ancien MDP, valide force nouveau MDP, audit log.
B2 Headers de sécurité HTTP core/security.py X-Frame-Options, CSP, HSTS, X-XSS-Protection, Referrer-Policy, Permissions-Policy, nosniff.
B5 Rate limiting global API core/security.py Max 100 requêtes/min par IP sur toute l'API. Middleware Starlette. Exclut /static/.
B6 Sanitisation des entrées schemas/chat.py Supprime balises HTML, caractères de contrôle, espaces excessifs. Max 1000 chars.
B7 Journalisation d'audit services/audit_logger.py Log fichier + console : LOGIN_OK, LOGIN_FAIL, REGISTER, PASSWORD_CHANGE, RATE_LIMIT, etc.

10. Fonctionnalités avancées

10.1 Détection des panneaux par texte

Le service sign_detector.py contient une base de 41+ panneaux routiers tunisiens avec :

  • Nom (FR + AR)
  • Mots-clés de détection
  • Catégorie (danger, interdiction, obligation, information)
  • Image SVG générée

Quand l'utilisateur pose une question mentionnant un panneau, le système détecte automatiquement les panneaux pertinents et affiche leurs images.

10.2 Détection par image (Vision IA)

L'utilisateur peut prendre une photo d'un panneau réel. L'image est envoyée à Groq Vision (Llama 4 Scout 17B) qui l'analyse et retourne :

  • Le nom du panneau identifié
  • Sa signification
  • Les règles associées

10.3 Mot de passe oublié par email

Flow en 3 étapes avec un code à 6 chiffres envoyé par email SMTP. Le code expire après 10 minutes. L'email contient un template HTML professionnel avec le branding de l'application.
